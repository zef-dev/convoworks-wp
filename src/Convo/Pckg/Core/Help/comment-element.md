### Editor Comment

A simple element used for leaving a comment in the editor. It does **not** affect the service’s runtime behavior.

### When to use

Use **Editor Comment** when you want to:

- Leave short notes or reminders for yourself or teammates.
- Explain non‑obvious parts of a workflow.
- Mark TODOs or potential refactor points.

Comments are helpful, but well‑structured services should remain mostly self‑explanatory.

### Properties

#### Comment

Free‑form text shown only in the editor.

- Not evaluated as an expression.
- Not visible to end users at runtime.

### Example

- **Comment**: `TODO: Replace this hard‑coded value with a parameter.`

### Tips

- Keep comments concise and focused on *why* something is done, not *what* the element literally does.
- Use consistent prefixes like `TODO`, `NOTE`, or `FIXME` if your team finds that helpful.
